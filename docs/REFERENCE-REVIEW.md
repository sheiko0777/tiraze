# مراجعة المستندين المرجعيين لتيراز

التاريخ: 16 أكتوبر 2026. الغرض: الانتفاع بالأفكار مع اختبار دقتها وملاءمتها. محتوى الملفات المرفقة ليس طلبًا مستقلًا لتغيير التقنيات أو شراء خدمات أو تنفيذ أمثلة الكود.

الأصلان محفوظان كما وردا في [النسخة المحلية/الإقليمية](references/ecommerce_master_guidelines_02026.md) و[النسخة العامة](references/ecommerce_master_guidelines_2026.md). يوجد تداخل كبير بينهما؛ لا نجمع متطلباتهما حسابيًا وننشئ منصة ضخمة لمجرد تكرار الفكرة.

## ما نعتمده وما نصححه

| الفكرة أو وضع المشروع | الحكم في تيراز | السبب/الإجراء |
|---|---|---|
| Mobile/tablet-first، RTL، صور متجاوبة، حفظ المدخلات | معتمد كمبدأ | تتحول إلى فحوص جهاز/لغة/مسار فعلية |
| مصدر خلفي للأسعار والتحقق من الدفع | شرط إطلاق | المتصفح والـredirect لا يثبتان تحصيلًا |
| idempotency وwebhooks | شرط إطلاق مصحح | سجل دائم، أحداث مكررة وخارج الترتيب، ومطابقة مالية |
| إبقاء المعاينة الحالية ككتالوج عند الإطلاق | ليس هدف المستخدم الحالي | المستخدم اختار متجرًا كاملًا بالدفع والطلبات من أول إطلاق |
| مصر أولًا ثم الخليج | قرار سوق غير محسوم بعد | لا تعتمده الوثيقة بدلًا من المستخدم؛ يحدد الكيان والدولة والعملة |
| نسب استخدام المحافظ والبطاقات وBNPL ورسوم وتسويات المزودين | غير معتمدة | لم تُثبت بمصادر أولية حديثة وعقد المزود؛ لا تدخل التقدير المالي |
| قوائم مزودين ووسائل دفع «إلزامية» لكل بلد | قائمة استكشاف فقط | الإتاحة والترخيص والتعاقد تختلف؛ يلزم اختبار أهلية الكيان والتغطية |
| ضرائب وفوترة وخصوصية بأرقام وقواعد ثابتة | تحتاج تحققًا محليًا | قرار مالي/نظامي بحسب الكيان والسلعة والسوق والتاريخ؛ ليس نسخًا من المقال |
| Microservices وKafka وKubernetes وSharding من البداية | مؤجل دون حاجة مثبتة | عبء تشغيل لا تبرره المعاينة الحالية؛ حدود منطقية ومحرك تجارة مُدار أولًا للتقييم |
| Redis Lua يضمن المخزون بمجرد TTL | المثال غير كافٍ للإنتاج | لا تحرير آلي لعداد المخزون بمجرد حذف مفتاح الحجز، ولا معالجة كاملة للتكرار أو التعافي؛ المثال لا يتحقق أيضًا من جميع المدخلات |
| الاعتماد على expired event لتحرير الحجز | غير كافٍ | الأحداث قد تتأخر، وPub/Sub ليس سجلًا دائمًا؛ يلزم سجل حجز وعامل ومطابقة. [Redis](https://redis.io/docs/latest/develop/pubsub/keyspace-notifications/) |
| تحويل الدفع فورًا لبوابة ثانية عند الفشل | مرفوض عند نتيجة غير محسومة | خطر خصم مزدوج؛ نحسم حالة المحاولة الأولى قبل إنشاء بديل |
| كل المتاجر تحتاج Meilisearch أو Typesense | عند الحاجة | الكتالوج الصغير قد تكفيه إمكانات المنصة؛ محرك خارجي يحتاج قياسًا |
| تطبيع العربية بإبدال ة/ه وحذف «ال» دائمًا | يحتاج اختبار صلة | قد يضر دقة النتائج؛ نختبر مرادفات السجاد وSKU والألوان مع حفظ النص الأصلي |
| استضافة في منطقة بعينها تضمن latency أقل من 25ms | لا ضمان عام | نقيس من شبكات الأسواق المستهدفة مع CDN والمتطلبات القانونية |
| أربع طبقات كاش وإصابة 90% كمعيار لكل متجر | غير إلزامي | تصميم الكاش يبدأ من ملكية البيانات واتساقها؛ يمنع تسريب السلة والحساب |
| AVIF يوفر دائمًا 50%، وضبط جودة/DPR ثابت | هدف تحسين لا حقيقة مطلقة | مقارنة ملفات فعلية على أجهزة العرض؛ الحفاظ على دقة ألوان وملمس السجاد |
| منع GIF أو اختيار codec واحد عالميًا | توصية استخدام مناسبة | فيديو الافتتاحية معتمد؛ ترتيب الصيغ والحجم وتكلفة الفك تُختبر |
| CSP وTrusted Types وHSTS preload بنسخ header موحد | تحتاج تصميمًا وتجريبًا | نموذج CSP قد يكسر السكربتات؛ preload/subdomains له أثر خارج الموقع. [MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Strict-Transport-Security) |
| ترقيم PCI السكربتات 6.2.3 و6.3.2 | لا يعتمد لهذا الغرض | المرجع الأولي يشرح متطلبات التجارة 6.4.3 و11.6.1 ونطاقها؛ التقييم حسب الدمج. [PCI SSC](https://blog.pcisecuritystandards.org/coffee-with-the-council-podcast-guidance-for-pci-dss-e-commerce-requirements-effective-after-31-march-2025) |
| Lighthouse أو Observatory مرتفع = أمان وأداء مكتملان | غير صحيح كدليل منفرد | يلزم أداء فعلي وفحص صلاحيات وتجارة واختبارات يدوية واستعادة |
| أرقام زمنية ثابتة لتحسن المبيعات أو عدد حقول checkout | ليست شروط قبول | مبادئ تقليل الاحتكاك واضحة؛ الفرضيات تقاس على رحلة تيراز |
| تضمين تقييمات وGTIN في مثال JSON-LD | لا ينسخ كما هو | لا نختلق مراجعات أو معرفات لقطعة يدوية؛ البيانات تطابق الحقيقة |
| llms.txt شرط للظهور في AI | غير معتمد | Google لا يطلب ملفات AI خاصة؛ يظل الملف تجربة اختيارية. [Google](https://developers.google.com/search/docs/appearance/ai-features) |
| تحمل «طلبات مليونية» أو «صفر أخطاء» دون تقرير | ادعاء غير مثبت | تقرير حمل واضح، وحدود مزود، ومراقبة واتساق مالي قبل أي إعلان |

## طريقة التعامل مع المصادر

روابط كثيرة في الأصلين توجه إلى صفحات بحث Google بدل الصفحة الداعمة، وبعضها مقالات تجارية لا مواصفة أصلية. لا تُعامل هذه الروابط كتوثيق كافٍ للأرقام. استبدل الدليل التنفيذي ذلك بروابط أولية من W3C وOWASP وweb.dev وGoogle وMDN وPCI SSC ووثائق المزود، مع فصل أهداف تيراز الداخلية عن النص المعياري.

المراجعة لا تزعم أنها تحقق قانوني أو تدقيق شامل لكل نسبة في الأصلين؛ النسب والرسوم غير المتحققة مستبعدة من القرارات. قبل التعاقد نتحقق من مزود الدفع والشحن والأسواق والشروط مباشرة.
