# ADR-0002: متجر مخصص لمصر ومسار قليل التكلفة

التاريخ: 17 أكتوبر 2026.

## الحالة

معتمد من المستخدم: متجر مخصص بالكامل، مصر وEGP أولًا، كاشير، حساب قبل الشراء، مخزون جاهز وطلبات تفصيل، COD حتى 10,000 جنيه بتأكيد موظف، وشحن بتسعير آلي وحجز يدوي. غير مفعل: أي اشتراك أو مورد إنتاج مدفوع.

مقترح هندسي مشروط بالإثبات: Astro/TypeScript وCloudflare Workers/D1/R2 وBetter Auth وResend. الحدود الزمنية للحجز والتأكد من البريد وسياسة الطرود إعدادات خطة تحتاج اعتمادًا قبل البيع.

## السياق والقرار

اختار المستخدم البناء المخصص بدل التجارة المُدارة، مع تفضيل المجاني والأقل تكلفة وخدمات سحابية مُدارة. لذلك تُستبدل توصية تقييم Shopify في ADR-0001 بهذا الاتجاه. تبقى متطلبات مصدر الحقيقة الخلفي وسلامة الأموال والمخزون والإطلاق الكامل سارية.

نبدأ بتطبيق معياري واحد ووحدات تجارة مشتركة، دون خدمات مصغرة أو Redis. تثبت مرحلة مبكرة المصادقة واستهلاك CPU ومعاملات D1 وتكامل كاشير قبل استكمال الواجهة والتجارة. أي فشل في الإثبات يعالج بقرار موثق قبل توسعة البناء.

التطوير وsandbox يبدأان بالمجاني؛ Workers Paid بدءًا من 5 دولارات شهريًا اقتراح للإنتاج عند الحاجة، مع استخدام زائد وخدمات أخرى بحسب القياس، وليس موافقة شراء. لا يستخدم GitHub Pages لاستضافة التجارة. كاشير Hosted Checkout يعالج بيانات البطاقة، وتيراز يحتفظ بالطلبات والتوقيعات والتسوية والصلاحيات.

## النتائج

الفريق مسؤول عن إدارة الطلب والمخزون والتكاملات والأمان والنسخ والتشغيل؛ لا تُختصر هذه الالتزامات لتناسب حصة مجانية. التسجيل إلزامي قبل الشراء، ويحل هذا اختيار المستخدم محل توصية guest checkout السابقة. COD ليس دفعة محصلة عند الإنشاء أو تأكيد الموظف. الشحن والتفصيل يبدآن بمسارات تشغيل محدودة وواضحة.

التفاصيل والمراحل والاختبارات والتكلفة والمدخلات وبوابات الإطلاق في [خطة التنفيذ](../IMPLEMENTATION-PLAN.md). هذه وثائق تخطيط، ولا تثبت أن المتجر الحالي أصبح جاهزًا للبيع.
