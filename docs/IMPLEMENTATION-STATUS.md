# حالة تنفيذ تيراز

18 أكتوبر 2026 — **تنفيذ جزئي، غير جاهز للبيع أو النشر**.

كاتب وحدات التنفيذ الحالية: Claude Code، بطلب صاحب المشروع. تولى Codex الإشراف والمراجعة وإضافة فحص مستقل وحماية ملفات التشغيل المحلية. توقف Claude عند حد استخدام الجلسة؛ الرسالة المتاحة تحدد إعادة الإتاحة الساعة 5 صباحًا بتوقيت القاهرة. لا تعني هذه الوثيقة اكتمال الخطة أو إغلاق بوابات الإطلاق.

## الموجود فعليًا

- هيكل pnpm workspace وإعداد TypeScript strict وVitest واعتماديات مثبتة مع lockfile.
- `packages/core`: أموال بالقروش، قواعد COD، مناطق وشحن مصر، حالات طلب/دفع/تنفيذ منفصلة، تحقق مدخلات، استيراد كتالوج، تشفير وتوقيع كاشير وadapter أولي لجلسات الدفع والاسترجاع.
- `packages/db/migrations/0001_commerce.sql`: مخطط التجارة وقيود المخزون وtriggers الحجز والتحويل والتحرير، والطلبات والأحداث والدفع والاسترجاع والشحن وoutbox والتدقيق.
- `packages/db/src`: خدمات أولية للكتالوج والسلة والعناوين والشحن والإعدادات والcheckout والدفع وoutbox والتدقيق. هذه خدمات غير موصولة بعد بواجهة أو API إنتاج.
- `apps/web/package.json`: اعتماديات التطبيق فقط؛ صفحات Astro وإعداد تشغيله والمصادقة ولوحة الإدارة لم تكتمل.
- المعاينة القديمة بهويتها وفيديو الهيرو ما زالت منفصلة. لم تُفعّل خدمات سحابية أو مفاتيح دفع أو اشتراكات، ولم يُنشر متجر إنتاج.

الحالات الست: 100 محاولة متزامنة لآخر قطعة لها فائز واحد؛ التراجع الكامل عند نفاد ثاني عنصر؛ رفض السعر القديم؛ منع المخزون السالب أو الحجز الزائد؛ تحرير قابل للتكرار؛ وتحويل حجز مرة واحدة. اختبرت الآلية بـSQL مباشرة، ولا تثبت وحدها صحة خدمة `createOrder` أو المسارات المستقبلية.

بيئة التحقق المحلية: Node 26.8.1، pnpm 10.30.3، TypeScript 6.0.3، Vitest 4.1.12، Miniflare 4.20260730.0. ضُبط تاريخ توافق محاكي الاختبار إلى `2026-08-01` بعد رفض runtime للتاريخ الأحدث. استخدمت الاختبارات `RETURNING` لعد الصفوف الأصلية؛ لأن `meta.changes` يتضمن آثار triggers.

## مراجعات لازمة قبل اعتماد الخدمات

هذه ملاحظات على كود جزئي، وليست ثغرات معلنة في متجر منشور؛ لا توجد API إنتاج موصولة به.

1. **نسخة السلة داخل المعاملة:** `createOrder` يتحقق من cartVersion قبل batch ثم يمسح السلة داخله. يلزم منع تغير السلة بين القراءة والكتابة بشرط ذري، واختبار أن إضافة عنصر أثناء checkout لا تضيع ولا تدخل طلبًا لم يراجعه العميل.
2. **التزامن في أحداث الدفع المتأخرة:** inbox لا يملك lease معالجة بعد، ومسار إعادة التخصيص قد يضيف حجوزات ثم لا يغير طلبًا سبق تأكيده بمسار متزامن. يلزم اختبار حدثين/عاملين متزامنين وضمان عدم بقاء حجز إضافي أو تنبيه خاطئ؛ شروط الصفوف المحمية يجب أن تفشل المعاملة كلها عند فقد السباق.
3. **ترابط الاسترجاع مع المزود:** يلزم ربط تأكيد refund بمرجع مزود موثق، وعدم الاكتفاء بمبلغ مطابق كبديل عام، والتحقق من العملية المالية عند الحاجة. كذلك يجب ألا يرجع رد API متأخر حالة succeeded إلى pending/unknown بعد وصول webhook ناجح.
4. **الإطلاق الافتراضي:** إعداد migration الحالي `checkout_enabled=true` لا يمثل موافقة بيع. يلزم جعله آمنًا افتراضيًا وربطه ببوابة تشغيل صريحة قبل توصيل API أو النشر؛ أمثلة الاختبار يمكن تفعيلها محليًا فقط.
5. **القيود العددية:** SQLite INTEGER affinity وحدها لا تثبت نوعًا صحيحًا صارمًا. تراجع قيود الأموال والكميات وقطعة SKU الفريدة مع تحقق مدخلات الإدارة واختبارات القيم غير الصحيحة.
6. **المهام والإشعارات:** تستكمل حدود المحاولات بعد تعطل العامل، ومدة lease مقابل زمن دفعة الإرسال، ومنع التسليم المكرر، ثم اختبارات outbox وتوصيل التنبيه.

## الاستئناف

ابدأ بقراءة [الخطة](IMPLEMENTATION-PLAN.md) و[ADR-0002](decisions/0002-custom-egypt-commerce.md) وهذه الحالة، ثم راجع `git status` قبل أي كتابة. لا تستبدل ملفات `app.js` أو فيديو الهيرو بمخرجات مساعدة لم تُراجع.

أول العمل التالي: إغلاق المراجعات أعلاه باختبارات خدمة D1 فعلية؛ استكمال Better Auth وهجراته وصلاحيات الموظفين وTOTP؛ ثم صفحات Astro وAPI والواجهة والإدارة وjobs وCI والتشغيل. لا يُستخدم `pnpm build` الحالي كأمر جاهز؛ إعدادات التطبيق وملفات entry/scripts المطلوبة ما زالت ناقصة.

تشغيل المعاينة الحالية يظل `python -X utf8 serve.py 8090`. للتحقق من الجزء المكتمل، ثبت الاعتماديات بـ`pnpm install`، ثم نفّذ أوامر الفحص المذكورة بالجدول. لا تُنفّذ migration على قاعدة إنتاج؛ الاختبار يستخدم قاعدة محلية معزولة وبيانات تركيبية.

بيانات المالك المطلوبة قبل الاختبار التجاري والإطلاق: حساب كاشير مفعل ومفاتيح sandbox/live عبر مخزن أسرار، كتالوج وأسعار ومخزون وصور معتمدة، عقد وتسعير شحن وحدود تحصيل، سياسات وفواتير معتمدة، بريد إرسال وموظفون وتنبيهات وميزانية موارد إنتاج.

المحاولة المساعدة لتوليد نص الكود تركها المستخدم تعمل صراحة؛ لا تُدمج مخرجاتها تلقائيًا ولا تُعتبر شغلًا منفذًا قبل أن تسلم ملفات وتراجع وتختبر.
