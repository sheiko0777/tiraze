# بوابات إطلاق متجر تيراز

الحالة: **غير جاهز للبيع حاليًا**. الإطلاق المستهدف يشمل الدفع والطلبات الفعلية. هذه قائمة تنفيذ، وليست تقرير نجاح. تُغلق كل بوابة بدليل مؤرخ مرتبط بالـcommit والبيئة والمالك. لا تُعدّ الخانة المفتوحة منجزة لأن وصفها موجود في الدليل.

الأدوار أدناه مسؤوليات مقترحة؛ يجب إسنادها لأشخاص محددين قبل الإطلاق. «غير مقاس» لا يعني فشلًا مثبتًا ولا نجاحًا مفترضًا.

## أدلة المعاينة الموجودة

- فحص تفاعل وعرض معزول: `interaction-verification.json`؛ يغطي المعاينة ولا يغطي دفعًا أو مخزونًا خلفيًا.
- متصفح محلي: `qa/browser-report.json`؛ لا يثبت وحده صلاحية Safari/iOS أو جودة WCAG كاملة.
- فيديو: `qa/hero-video-report.json`؛ تشغيل/إيقاف على الكمبيوتر والموبايل وتقليل الحركة.
- الهوية ومحتوى السجاد منفذان؛ صور المنتجات تصورات وليست مخزونًا تجاريًا معتمدًا.

## قرار الإطلاق

كل شرط خاص بالأموال أو المخزون أو صلاحيات العملاء أو البيانات أو الاستعادة يجب إغلاقه قبل البيع. الاستثناءات غير الحرجة تسجل بمالك وتاريخ وخطر وخطة معالجة. تقرير الإطلاق يحدد commit وبيئة وأدلة، وأي شرط غير منطبق يشرح السبب. لا تعويض لفشل أمني أو مالي بدرجة أداء مرتفعة.

## ترتيب العمل التالي

1. إغلاق B01–B04 واختبار ملاءمة المنصة؛ لا فرض بلد أو مزود من المستندات المرجعية.
2. بناء رحلة تجريبية كاملة بمنتج فعلي واحد ومخزون 1، مع تحصيل واسترجاع وتجربة فشل.
3. تنظيم المصدر ونقل كتالوج تيراز الحقيقي واللغات وSEO إلى مسار الإنتاج المختار.
4. تكامل الاختبارات والأمان والمراقبة والاستعادة والشحن وإغلاق البوابات.
5. إطلاق مضبوط ومتابعة مالية وتشغيلية؛ قياس CWV الميداني حين تتوفر عينة كافية.
